01　问题与产品定位

现有前端将农场指标、作物健康、气象预警与监测记录集中展示，但数据以模拟值为主。农场管理者仍需自行把“会下多少雨”“哪些地块受影响”和“谁来处理”串成执行计划。天气智农的MVP目标是把气象风险转化为有依据、可追踪的农事任务。

核心场景：管理者发现未来24小时强降雨风险 → 核对地块和作物阶段 → 询问农事助手 → 查看依据与缺失信息 → 人工确认排水巡检任务 → 跟踪现场反馈。

用户主要需求权限
农场管理者快速判断风险、分配任务、追踪处理本农场查看、任务创建与分配、确认建议
农技人员核对农业建议、调整任务、补充知识本农场查看、审核建议、填写反馈
现场人员手机查看任务、登记监测值、反馈执行分配给自己的任务与授权地块；最小化数据访问
农场管理员维护人员、地块、数据源农场设置与授权；不能读取其他农场数据

成功目标与测量方式

以下均为候选验收目标，待真实数据源和试用规模确定后校准，不代表现有成绩。

目标定义候选门槛
风险到任务的流程可用验收人员在指定场景内完成预警→建议→任务→反馈全部核心验收场景通过；5名试用者至少4名独立完成
建议有事实依据关键事实可对应到工具返回值、来源和时间关键事实依据覆盖率≥95%；虚构事实比例≤2%
失败可恢复超时、缺字段、过期数据有明确提示与后续操作全部预定义异常用例通过
执行可追溯每项任务可追溯预警、建议版本、确认人和状态变化抽查任务追溯字段完整率100%

03　核心流程与交互契约

选择农场/地块 → 查看天气与数据状态 → 打开风险预警
          ↓                          ↓
     补充监测记录              问农事助手（携带上下文）
                                     ↓
              缺信息 → 澄清；数据异常 → 说明并允许重试
                                     ↓
                       展示建议、依据、有效期
                                     ↓
                       用户确认 → 创建任务草稿
                                     ↓
                  分配负责人 → 执行 → 填写反馈 → 完成

助手不会直接执行农事设备动作。创建任务前，用户必须查看地块、行动、负责人和截止时间。重新生成建议形成新版本，已确认任务保留原建议快照。

04　功能需求与验收标准

ID / 优先级需求验收标准
FR-01 / P0登录、权限与农场上下文未登录访问跳转登录；后端独立检查用户与farm_id；跨农场请求拒绝；退出使服务端会话失效。演示账号仅用于原型。
FR-02 / P0地块档案录入地块名称、坐标、面积及单位、作物、生育期；面积须>0；坐标合法；缺生育期时显示“待补充”，不凭空补齐。切换地块更新相关卡片和对话上下文。
FR-03 / P0天气数据展示提供方、地点、观测/预报时间、拉取时间、有效区间、时区、单位；观测与预报区分；空值显示“暂无”；获取失败显示错误和重试，不显示零。
FR-04 / P0农业风险预警展示来源类型、风险原因、适用地块和规则版本；农业风险提示与官方气象预警分开展示；命中规则记录触发值；无规则不得生成定量灾害结论。
FR-05 / P0Agent问答携带地块/作物/阶段；缺关键字段先澄清；依据来自工具数据；气象工具失败停止依赖该数据的结论；每条建议展示来源、有效期和限制。
FR-06 / P0任务确认用户确认后创建草稿；选择负责人和截止时间后提交；显示关联预警与建议；重复点击不重复创建；失败保留输入；任务不能跨农场分配。
FR-07 / P0任务状态与反馈状态为草稿→待处理→进行中→已完成；允许待处理/进行中→已取消；已完成须填写结果；取消需理由；已完成任务不直接回退，创建跟进任务。
FR-08 / P0监测填报站点、地块、时间、因子、数值、单位必填；时间不能晚于服务器时间5分钟；数值有限且符合因子范围；保存成功返回record_id；失败可重试。
FR-09 / P0通知中心按类型与关键词筛选；单条/全部已读保存；预警通知跳详情；无结果提示清除筛选；重要预警处理记录不随通知删除而丢失。
FR-10 / P0来源与审计保存request_id、工具参数/结果摘要、模型版本、知识版本、数据时间、用户确认和状态变更；用户可查看依据；敏感字段在导出中脱敏。

数据时效规则（候选配置）

预报拉取距当前时间超过6小时标记“需更新”；实时观测超过30分钟标记“过期”；官方预警以提供方有效期为准。超过有效期不得继续显示为当前风险。阈值根据实际提供方更新频率调整，必须配置化并记录版本。未知时间等同无法核验时效。

监测字段校验

因子单位格式/范围（录入防错用）
温度℃有限数值，-60～60；不等同作物受害阈值
空气湿度、土壤体积含水率%0～100；两者不得混用；土壤方法需记录
降水mm≥0，必须带统计起止时间；异常大值进入复核
风速m/s≥0，注明平均/阵风和观测时间

附件属于P1：图片PNG/JPEG ≤5MB、报告PDF ≤10MB；服务端检查格式、扫描文件并限制访问。原型不模拟上传成功，不把选中附件视为已保存。

05　Agent设计

采用可观测的ReAct工具循环：模型选择工具→后端校验参数与权限→执行工具→返回观测→模型继续或生成建议。前端展示工具进度和依据摘要；不展示或保存模型私有思维链。此架构是新增设计，未在原仓库中发现已实现证据。

工具（拟定）输入输出 / 约束
get_field_contextfield_id地块、作物、阶段、位置；farm_id从登录上下文注入
get_weather_forecastfield_id、起止时间预报值、单位、时间、提供方、forecast_id；不可把预报标为实测
get_observationsfield_id、因子、时间段监测值、设备/人工来源、观测时间、质量状态
get_active_alertsfield_id有效预警、来源类型、触发规则与版本
search_agri_knowledge作物、阶段、灾害/操作经审核知识片段、来源、适用区域和版本；未检索到就说明不足
prepare_task_draft建议ID、行动摘要只生成草稿预览；不写入任务，不控制设备

单次请求候选上限：6轮工具循环、单工具8秒、整轮45秒；到上限停止并说明已完成查询与尚缺信息。只有瞬时网络故障允许有限重试，权限错误与参数错误不能盲目重试。写任务由用户确认后的独立接口完成。

输出协议

{
  "status": "answer | needs_clarification | insufficient_evidence | tool_error",
  "request_id": "...", "field_id": "...", "recommendation_id": "...",
  "summary": "结论或澄清问题",
  "actions": [{"action": "...", "reason": "...", "urgency": "..."}],
  "evidence": [{"source_id": "...", "source_type": "forecast | observation | knowledge",
                "data_time": "ISO8601+08:00", "unit": "...", "excerpt": "..."}],
  "missing_fields": [], "limitations": [], "valid_until": "..."
}

不显示未经校准的模型置信度百分比。用“依据充分 / 需要补充 / 无法核验”解释证据状态。农药品种、用量与混配问题需适用作物、病虫害确认和正式登记信息；MVP不给具体处方，转农技人员复核。

06　数据对象与接口草案

对象关键字段一致性要求
Fieldid、farm_id、name、lat/lon、area、area_unit、crop、growth_stage位置不可为空；阶段变更带时间与操作人
WeatherSnapshotid、provider、location、issued_at、fetched_at、valid_from/to、values、units、quality预报与观测类型独立；空值不能补成0
RiskAlertid、field_id、source_type、severity、reason、rule_version、valid_until、status保存触发值与来源；相同事件去重
Recommendationid、field_id、request_id、answer、evidence、model_version、knowledge_version已确认后不可覆盖；重新生成新版本
Taskid、farm_id、field_id、recommendation_id、owner、due_at、status、feedback、version幂等创建；状态更新检查版本避免覆盖
Observationid、field_id、station、factor、value、unit、observed_at、quality、operator重复源记录去重；异常记录不参与自动判断
拟定接口用途
GET /api/fields；GET /api/fields/{id}/weather地块与气象快照
GET /api/alerts?field_id=...预警列表、详情与时效状态
POST /api/agent/chat接收session_id、field_id、message；返回输出协议，支持进度事件
POST /api/tasks；PATCH /api/tasks/{id}人工确认创建、状态与反馈；创建带Idempotency-Key
POST /api/observations校验后保存监测记录；返回记录ID
GET /api/notifications；PATCH /api/notifications/{id}通知查询与已读保存

所有接口由服务端强制校验农场权限；401登录失效、403无权限、422字段错误、409版本冲突、429调用受限、503数据源不可用。错误响应带request_id、可读提示、是否可重试。接口尚未实现。

07　体验与非功能要求

  • 默认桌面1440宽，移动端390宽；重要操作在移动端可完成，表格允许横向滚动。
  • 预警不能只靠颜色区分；同时显示文字等级、图标和时间。所有输入具备可见标签，键盘可操作，焦点可见。
  • 一般页面候选P95首屏≤3秒；Agent响应候选P95≤30秒；错误1秒内说明。实际网络与模型环境下测量。
  • 历史数据保留策略拟为运行日志90天、已确认任务365天；由农场业务和合规要求最终确定；支持导出及按授权删除。
  • 只传输决策所需位置与作物信息；第三方模型调用前明确数据处理范围。禁止将密钥写入浏览器。

08　验收、迭代与风险

阶段完成条件依赖
M0 设计评审本PRD、可点击原型、评测用例逐条评审选择试点农场和作物
M1 数据闭环真实鉴权、地块、气象、监测、预警与任务保存通过验收气象提供方、数据库与部署环境
M2 Agent联调工具协议、知识检索、来源展示、异常恢复可运行模型服务、农技审核知识库
M3 离线评测冻结测试集、真实运行日志、人工评分和失败修复固定模型与提示词版本、农技评审
M4 小范围试用现场反馈、错误与成本复核后决定是否扩展使用授权与试点负责人

关键风险是气象粒度与地块尺度不匹配、知识适用范围错误、过期信息被当作当前信息、操作缺少执行留痕。分别通过位置与粒度声明、知识来源和区域标签、时效门槛、任务审计处理。全部实现前，只能作为原型与设计展示。
