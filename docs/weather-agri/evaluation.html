6. 接口接入与本地验证

模型接入支持Ollama /api/chat和兼容/chat/completions协议，配置取自AGRI_PROVIDER、AGRI_BASE_URL、AGRI_MODEL、AGRI_API_KEY。密钥不会出现在前端、日志或交付包中。本轮模拟HTTP服务验证工具返回解析、参数错误、越权、写工具拒绝、循环上限、缺证据及403响应；模拟服务返回标为mock-model。

模型只负责只读工具规划，最终建议由规则门控生成，评分范围是工具规划和业务约束。后续若评估自然语言质量、引用解释或对复杂农事情境的推理，应另建测试契约，不能将本轮分数直接沿用。

python docs/weather-agri/agent/evaluate.py
python docs/weather-agri/agent/test_backend.py
# 配置可用模型后另存结果，避免覆盖本地参考结果
python docs/weather-agri/agent/evaluate.py --engine model --output work/model-evaluation

7. 真实模型评测计划

服务配置后先验证工具调用兼容性，再分别统计聊天工具规划用例与任务/监测业务用例；记录模型名称、版本、请求参数、调用次数、完成/中止数、tokens、端到端耗时和失败类别。每例至少重复3次，采用独立保留集，并由农技人员评审适用性、证据完整性和人员安全；成本须按当次服务账单核验。当前没有给这些项目填入估算成绩。

上线候选门槛：越权、未确认写入、危险入田建议等严重错误必须为0；其他质量门槛应在真实评审完成后确定。当前40条有限样本不足以证明错误概率为0。
